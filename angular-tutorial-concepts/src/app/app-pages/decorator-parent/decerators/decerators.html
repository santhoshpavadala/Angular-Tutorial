Topic 2: Decerators

What is a Decorator in Angular?

A Decorator is a special TypeScript function that adds metadata to a class, method, property, or parameter.
In Angular, decorators tell Angular how a class or property should behave.

A decorator is a function that adds metadata to a class, property, method, or parameter so Angular knows how to process and use it.

    Angular uses decorators to define things like:
  • Components
  • Directives
  • Services
  • Modules
  • Input/Output bindings
  • Dependency Injection

Types of Angular Decorators

Angular decorators are mainly 4 types:

  • Class Decorators: Applied to classes: @Component, @Directive, @Pipe, @Injectable, @NgModule
  • Property Decorators: Applied to class properties: @Input, @Output, @ViewChild
  • Method Decorators: Applied to methods: @HostListener
  • Parameter Decorators: Applied to constructor parameters: @Inject, @Optional

Property Decorators: These decorators are applied to class properties.

@Input Decorators:

@Input allows data from parent component to child component.

@Output Decorators:

@Output is used to send data from child component to parent component.

@ViewChild

Used to access a child component or DOM element from the parent component.

Q3. What is the purpose of @Component?

@Component defines metadata such as the selector, template, styles, imports, and other configuration that Angular needs to create and use a component.

Q4. What are @Input and @Output?

@Input allows a parent component to pass data to a child component. @Output allows a child component to emit events that the parent can handle.

            
                import 
                Component,
                Input,
                Output,
                EventEmitter
                 from '@angular/core';

                @Component(
                selector: 'app-user-card',
                standalone: true,
                template: `
                    
 name 

                    
                `
                )
                export class UserCardComponent 
                @Input() name = '';

                @Output() selected = new EventEmitter< string>();

                select() 
                    this.selected.emit(this.name);
                

            Parent template:
            app-user-card [name]="userName" (selected)="onUserSelected($event)"/>

Q5. What is the difference between @Input and signal-based input()?

Both define component inputs. Decorator-based @Input exposes a property that receives a value from the parent. Signal-based input() exposes the input as a read-only Signal, allowing reactive reads using function-call syntax.

            
                import Component, input from '@angular/core';
                @Component(
                selector: 'app-user',
                standalone: true,
                template: `
name()
`
                )
                export class UserComponent 
                name = input('Guest');

Q6. What is the difference between @Component and @Directive?

A component is a directive with its own template. A directive adds behavior to an existing element or controls view structure without defining its own component template.

Q7. What are @HostListener and @HostBinding?

@HostListener listens to events on a directive or component's host element. @HostBinding binds a class property to a property, attribute, or class on the host element.

            
                import 
                    Directive,
                    HostListener,
                    HostBinding
                 from '@angular/core';

                @Directive(
                    selector: '[appHover]',
                    standalone: true
                )
                    export class HoverDirective 
                    @HostBinding('class.active') isActive = false;

                    @HostListener('mouseenter')
                    onMouseEnter() 
                        this.isActive = true;
                    

                    @HostListener('mouseleave')
                    onMouseLeave() 
                        this.isActive = false;

Q. How would you design a reusable modal component?

I would build a component with clear inputs for title, visibility, and configuration, and outputs for close or confirmation events. For more advanced use cases, I would consider Angular CDK Dialog or Material Dialog rather than manually implementing focus management and accessibility behavior.

ContentChild: Projected Search Input.

@ContentChild is used to access content projected from a parent component into a child component via ng-content. It is commonly used in reusable components such as cards, modals, widgets, and form wrappers, and is typically accessed inside ngAfterContentInit().

@ContentChild is used to access content projected into a component using ng-content. It allows a child component to access elements, directives, or components that are passed from the parent through content projection.

Template Reference Variable

A Template Reference Variable is a local template variable created using the # symbol that provides access to a DOM element, Angular component, directive, or form instance within the template. It is commonly used for form handling, element access, component interaction, and with @ViewChild.
