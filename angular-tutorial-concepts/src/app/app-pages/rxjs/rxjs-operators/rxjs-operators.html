Topic 13: Rxjs-Operators

RxJS and Observables in Angular

1. What is RxJS?

RxJS (Reactive Extensions for JavaScript) is a library for working with asynchronous data streams using Observables and operators.
In Angular, RxJS is commonly used for:

  • Handling HTTP responses
  • Reacting to form value changes
  • Managing search suggestions
  • Combining multiple API calls
  • Handling user events
  • Sharing data between components through services
  • - Managing asynchronous operations and errors

For example, when a user types into a search field, each keystroke creates a sequence of events. RxJS can filter out unnecessary events, wait until typing pauses, and trigger the latest API request.

2. What is an Observable?

An Observable represents a stream of values that can arrive over time.
For example, an API might return data once, while a search input may emit values repeatedly.

Observable lifecycle

  1. Observable: Produces values over time
  2. Observer: Receives values, errors, and completion
  3. next() Emits a value
  4. error() Signals failure
  5. complete() Signals the end

An Observable can emit zero or more values, followed by either completion or an error. Once it completes or errors, it cannot emit further notifications.

3. What is an Observer?

An Observer is the object that receives notifications from an Observable.
It can define three callbacks:

Observable vs Observer

  • Observable: produces notifications.
  • Observer: consumes notifications.
  • - Subscription: represents the execution and gives you a way to unsubscribe.

4. What is subscribe()?

subscribe() starts listening to an Observable. For a cold Observable such as a typical HttpClient request, subscribing initiates the request.

For a typical successful HTTP request, the Observable emits the response and completes. If the request fails, it emits an error instead.

What is a Subscription?

A Subscription represents an active subscription and provides unsubscribe().

Unsubscribing stops that subscriber from receiving further notifications. For cancellable sources such as Angular HTTP requests, it can also cancel ongoing work.

Interview question: Does every Observable require manual unsubscription?

No. Finite Observables such as typical HTTP requests complete automatically. Long-lived streams, such as form changes or intervals, may need lifecycle-based cleanup.

6. Creating Observables: of, from, interval, timer

These creation functions are frequently asked about in interviews.

of()

Emits the supplied arguments as individual values.

from()

Converts an iterable or Promise into an Observable.

interval()

Emits an increasing sequence of numbers at regular intervals, starting at zero.

This stream does not complete on its own, so manage its subscription lifetime when necessary.

timer()

Emits after a specified delay. With a period argument, it can continue emitting.

Interview question: What is the difference between of() and from()?

of([1, 2, 3]) emits the entire array as one value. from([1, 2, 3]) emits three individual values.

7. RxJS operators: map, filter, tap

Operators transform or act on values flowing through an Observable pipeline. The pipe() method connects these operators.

map()

Transforms each emitted value.

filter()

Emits only values satisfying a condition.

tap()

Performs a side effect without changing the emitted value. Useful for logging or debugging.

Interview distinction:

  • map() transforms values.
  • filter() decides which values pass through.
  • tap() performs side effects without transforming the stream.

8. Subject and its types

A normal Observable does not necessarily allow you to push values into it manually. A Subject is both an Observable and an Observer: you can subscribe to it and call next() to emit values.

A plain Subject does not replay earlier values to new subscribers.

BehaviorSubject:

A BehaviorSubject requires an initial value and gives new subscribers the latest value immediately.

Real-world use: Sharing the current user, selected theme, or application state between components.

ReplaySubject

A ReplaySubject can replay a configured number of previous values to new subscribers.

AsyncSubject

An AsyncSubject emits only the last value, and only when it completes.

Comparision

                
Type	        Initial value required?	            What a late subscriber receives
Subject	                No	                        Future values only
BehaviorSubject	        Yes	                        Latest value, then future values
ReplaySubject	        No	                        Configured history, then future values
AsyncSubject	        No	                        Final value after completion, if one was emitted

Interview question: How do you share data between unrelated Angular components?

One approach is to expose a BehaviorSubject or a signal from a shared service. Components subscribe to the stream or read the signal to receive updates. For new Angular applications, signals may be simpler for synchronous shared state, while RxJS remains particularly useful for asynchronous streams.

9. Higher-order mapping operators

This is one of the highest-priority RxJS interview topics.

A higher-order Observable is an Observable that emits other Observables. Mapping operators determine how those inner Observables are handled.

The four operators to understand are:

  • switchMap
  • mergeMap
  • concatMap
  • exhaustMap

switchMap()

Switches to the latest inner Observable and unsubscribes from the previous inner subscription.

Use case: Search boxes, where older searches become irrelevant when a newer term arrives.

mergeMap()

Subscribes to multiple inner Observables concurrently.

Use case: Independent API requests that can run concurrently.

concatMap()

Processes inner Observables sequentially, waiting for each to complete before starting the next.

Use case: Operations that must be processed in order, such as sequential updates.

exhaustMap()

Ignores new source emissions while the current inner Observable is still active.

Use case: Preventing repeated login submissions while one login request is in progress.

The most important comparison

                
Operator	Handles a new emission by…	                    Typical use
switchMap	Replacing the previous inner subscription	    Search suggestions
mergeMap	Running concurrently	                        Independent requests
concatMap	Queueing in order	                            Sequential operations
exhaustMap	Ignoring it while busy	                        Preventing duplicate submissions

Important nuance: Unsubscribing from an Angular HTTP Observable usually aborts the client-side request. It does not guarantee that the backend has stopped processing an operation that it has already received. For important writes, backend-side idempotency and validation still matter.

10. Combining multiple Observables

forkJoin()

Waits for all supplied Observables to complete, then emits their final values together.

Use case: Loading several independent API resources before preparing a dashboard.

Note that if one source errors, forkJoin errors unless you handle that source's error. If a source never completes, forkJoin does not emit.

combineLatest()

Emits a combined latest-value result whenever any input emits, after every input has emitted at least once.

Use case: Reacting to multiple filters or form controls.

If a source is a BehaviorSubject, its current value is emitted immediately to a new subscriber. For form controls, you may use startWith() when you need the current value included.

zip()

Pairs values by their emission index: the first value from each source, then the second from each, and so on.

Comparison

                
Operator	    Emission behavior	                        Typical use
forkJoin	    One result after all sources complete	    Initial dashboard data
combineLatest	Latest values whenever an input changes	    Reactive filters
zip	            Pairs corresponding emissions by position	Coordinated sequences

11. debounceTime() and distinctUntilChanged()

These operators are very common in search and reactive forms.

debounceTime()

Waits until a specified period passes without a new emission, then emits the latest value.

This reduces requests while the user is typing.

distinctUntilChanged()

Suppresses consecutive duplicate values.

By default, it uses === comparison, so objects generally require a custom comparator if you want structural comparison.

Interview question: Why use both operators together?

debounceTime() waits for typing to pause. distinctUntilChanged() avoids repeating a request for the same consecutive search value.

12. Error handling: catchError(), retry(), finalize()

catchError()

Catches an Observable error and returns another Observable, such as a fallback or a rethrown error.

Here, a failed request becomes an empty array. This is appropriate only if an empty list is a safe fallback for the application; otherwise, preserve the error for the UI to handle.

retry()

Resubscribes to the source after an error, for a configured number of attempts.

retry(2) allows up to two retries after the original attempt. Use it selectively for transient errors; don't blindly retry validation failures or non-idempotent write operations.

finalize()

Runs cleanup when the stream completes, errors, or is unsubscribed.

Remember: catchError() handles errors, retry() retries, and finalize() performs cleanup.

13. Subscription management and memory leaks

A memory leak can occur when a long-lived Observable subscription remains active after the component is destroyed and continues retaining or updating resources.

Option 1: takeUntilDestroyed() — recommended for modern Angular

The subscription is cleaned up when the component or injection context is destroyed.

Option 2: takeUntil()

This traditional pattern uses a notifier Observable to terminate a subscription.

Option 3: take()

Automatically completes after receiving a specified number of values.

Interview question: Should we manually unsubscribe from every HTTP request?

Usually not for standard finite Angular HTTP Observables because they complete after their response or error. However, subscriptions to long-lived streams, such as valueChanges, interval, or a Subject, should be managed when their lifetime exceeds the component's lifetime.

SwitchMap

switchMap is a higher-order RxJS operator that maps a value to a new Observable and automatically cancels the previous Observable when a new value arrives.

    Simple meaning:
  • When a new request comes
  • It cancels the previous request
  • And switches to the latest one

That’s why it’s called switchMap.

Why Do We Even Need switchMap?

    Because sometimes:
  • You trigger an API call based on user action
  • User triggers again before first API finishes
  • You don't want old response anymore
  • Without switchMap → both responses come
  • With switchMap → only latest response is kept

MergeMap Operator

mergeMap maps each emitted value to an inner Observable and subscribes to all of them simultaneously without cancelling previous ones.

  • Every input triggers an API
  • All API calls run
  • All responses are processed

concatMap

concatMap maps each emitted value to an inner Observable and executes them sequentially, waiting for each one to complete before starting the next.

  • One request at a time
  • Next starts only after previous completes
  • Maintains order

exhaustMap

exhaustMap maps each emitted value to an inner Observable, but ignores new emissions while the current inner Observable is still running.

    Simple meaning:
  • If one request is running
  • Ignore new triggers
  • Until current completes
  • It “exhausts” the current observable before accepting new ones.
