Angular Forms

This section is important for your interviews because forms, validation, dynamic forms, API submission, and error handling are common frontend responsibilities.

1. What are Angular Forms?

Angular Forms provide APIs for:

  • Capturing user input
  • Managing form state
  • Validating user input
  • Displaying validation errors
  • Submitting data
  • Updating form values
  • Handling dynamic fields

For example, a user registration form may contain:

  1. Name
  2. Email
  3. Password
  4. Confirm Password
  5. Phone
  6. Skills
  7. Submit

Angular provides two major approaches:

Template-driven forms

Form logic is primarily defined in the HTML template.
Uses: FormsModule, ngForm, ngModel, ngModelGroup

Reactive forms

Form structure and validation are primarily defined in TypeScript.

Uses: ReactiveFormsModule, FormControl, FormGroup, FormBuilder, FormArray

12. Important form states

Every Angular form control has several useful states.

                
| Property      | Meaning                                           |
|---            |                                                ---|
| `valid`       | All validators pass |
| `invalid`     | At least one validator fails |
| `touched`     | User has interacted with the control and left it |
| `untouched`   | User hasn't blurred/interacted with it |
| `dirty`       | Value has changed |
| `pristine`    | Value hasn't changed |
| `enabled`     | Control accepts interaction |
| `disabled`    | Control is disabled |
| `pending`     | Async validation is in progress |

Very common interview question

What is the difference between touched and dirty?

touched means the user has interacted with the control and it has lost focus.
dirty means the control's value has been changed.

For example: Click input → type nothing → click outside

The control can become:
touched = true
dirty = false

But: Click input → type something, makes it: dirty = true

20. Cross-field validation

Sometimes validation depends on multiple fields.

Example: Password & Confirm Password. We need to make sure they match.

This validation belongs at the FormGroup level because it compares two controls.

Why is password matching usually implemented at the FormGroup level?

Because the validation depends on the values of two controls, not just one individual control.

24. Important Angular Forms interview questions

Q1. Template-driven vs Reactive Forms?

Template-driven forms are template-centric and simpler for small forms.
Reactive forms are model-driven, provide explicit form structure in TypeScript, and are generally better suited to complex enterprise forms, dynamic controls, and advanced validation.

Q2. What is FormControl?

Represents an individual form control and tracks its value, validation state, and interaction state.

Q3. What is FormGroup?

A collection of related form controls represented as a group.

Q4. What is FormArray?

A dynamic collection of controls or form groups.

Q5. What is FormBuilder?

A service that provides convenient methods for creating reactive form controls, groups, and arrays.

Q6. setValue() vs patchValue()?

setValue() → complete structure required
patchValue() → partial update allowed

Q7. What does markAllAsTouched() do?

It marks all controls in a form as touched.

this.employeeForm.markAllAsTouched();

This is commonly used when the user submits an invalid form so that validation messages become visible.

Q8. What does getRawValue() do?

It returns the form's values including disabled controls.

const data = this.employeeForm.getRawValue();

Q9. What does a custom validator return?

valid: null

Invalid: errorName: true

Q10. What is valueChanges?

An Observable that emits whenever the value of a control or form changes.

Q11. What is statusChanges?

An Observable that emits whenever the validation status changes.

Q12. What is an async validator?

A validator that performs asynchronous validation, commonly using an API call, and returns an Observable or Promise.

Reactive Forms

What are Reactive Forms?

Reactive Forms in Angular are model-driven forms, where the form structure, validation, and logic are defined in TypeScript, not HTML.
The UI only reflects what the form model says.

Reactive Forms are Angular forms where form controls are created and managed in the component class using FormControl, FormGroup, and FormArray, providing better control, scalability, and testability.

Core Building Blocks (VERY IMPORTANT)

1.FormControl: Represents one input field

syntax: new FormControl('', Validators.required)

Example: Username, Email, Password

2. FormGroup: A collection of form controls

new FormGroup( username: new FormControl(''), password: new FormControl('') )

3. FormArray: Used for dynamic fields

new FormArray([ new FormControl('') ]);

4. Validators

Validators.required
Validators.minLength(6)
Validators.email
Validators.pattern()

Forms Array

What is FormArray?

FormArray represents an array (list) of form controls or form groups where the number of controls is dynamic.
Controls are accessed by index, not name.

syntax: 'new formGroup([])'

Real Use Cases (FormArray)

  • Add multiple skills
  • Multiple phone numbers
  • Multiple addresses
  • Product variants
  • Dynamic questionnaires

Structure changes at runtime

What is FormGroup?

FormGroup represents a group of named form controls where the structure is known and fixed.
Each control is accessed by a key.

syntax: 'new formGroup()'

Real Use Cases (FormGroup)

  • Login form
  • Registration form
  • Profile update form
  • Settings page
  • Address form (single address)

Structure does NOT change at runtime

One-Line Killer Answer (Use This)

What are Async Validators?

Async Validators in Reactive Forms (in Angular) are used when validation depends on asynchronous operations like:

  • HTTP API calls
  • Server-side checks
  • Database lookups

They return an Observable or Promise, not a value immediately.

An async validator is a function that performs asynchronous validation and returns an Observable or Promise that emits either null (valid) or a validation error object.

Async validators are used when validation depends on server responses and return an Observable or Promise that resolves to either a validation error or null.
