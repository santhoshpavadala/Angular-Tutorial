1. What is HttpClient?

Angular's HttpClient is used to communicate with backend APIs over HTTP.

Typical flow:

                
                    Angular Component
                        ↓
                    Angular Service
                        ↓
                    HttpClient
                        ↓
                    REST API
                        ↓
                    Backend
                        ↓
                    Response
                        ↓
                    Angular Service
                        ↓
                    Component

For example: GET /api/employees; returns employee data.

Important interview distinction: 401 vs 403

401 generally means the request lacks valid authentication credentials.
403 means the server understood the request but refuses access because the authenticated caller doesn't have sufficient permission.

13. HTTP Error Handling

Angular provides HttpErrorResponse.

But handling every error independently inside every component can become repetitive. A better architecture is to centralize common error handling using an interceptor or service.

14. catchError

catchError is an RxJS operator used to handle errors in an Observable pipeline.

Why return throwError()?

If you want the component or another downstream subscriber to know that the request failed, you need to propagate the error.
Otherwise, you could transform the error into a fallback value if that is appropriate.

21. Multiple interceptors

You can register multiple interceptors: provideHttpClient

                
provideHttpClient(
  withInterceptors([
    authInterceptor,
    loadingInterceptor,
    errorInterceptor
  ])
)

Conceptually:
Request
   ↓
Auth Interceptor
   ↓
Loading Interceptor
   ↓
Error Interceptor
   ↓
Backend
   ↓
Response

The interceptors form a request/response pipeline.

Interview question: Can we have multiple HTTP interceptors?

Answer: Yes. Multiple interceptors can be registered and participate in the HTTP pipeline. Their configured order matters, so interceptors should be designed with that pipeline behavior in mind.

22. API Service Architecture

For a professional Angular application, avoid putting all API calls into one giant service.

Instead:

This gives you a clean separation:

   ↓

   ↓
API

23. Retry concepts

Sometimes a request may fail temporarily because of network issues or transient server failures.
RxJS provides retry().

                
return this.http
  .get< Employee[]>('/api/employees')
  .pipe(
    retry(2)
);

This can retry the Observable subscription when an error occurs.
But don't blindly retry every HTTP error.
For example, retrying:

400 Bad Request
401 Unauthorized
403 Forbidden
404 Not Found

usually doesn't fix the underlying problem.

Retry is more appropriate for carefully selected transient failures, such as certain network or temporary server failures.

24. Request cancellation

Angular HTTP requests return Observables.
If a newer request makes an older request irrelevant, RxJS operators such as switchMap can cancel/unsubscribe from the previous inner request.
This is extremely useful for search.

HTTP Interceptor in Angular

An HTTP Interceptor is a special Angular service that sits between your app and the backend API.

It can inspect, modify, or handle:
Outgoing HTTP requests
Incoming HTTP responses
Errors globally
Think of it as a middleware layer for all HTTP calls.

Why do we use HTTP Interceptors? (Real-Time Use Cases)

In real projects, interceptors are used for:

  • Add Auth Token (JWT) to headers
  • Handle API errors globally
  • Show / hide loader (spinner)
  • Log API requests & responses
  • Modify request URLs or headers
  • Retry failed requests

Instead of repeating code in every service, interceptor does it once globally

How HTTP Interceptor Works (Flow)

  • Component calls API via HttpClient
  • Request goes to Interceptor
  • Interceptor modifies request (if needed)
  • Request hits backend
  • Response comes back through Interceptor
  • Component receives final response
