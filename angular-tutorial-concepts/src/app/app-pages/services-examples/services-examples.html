Angular Services – Brief Introduction

A Service is a reusable TypeScript class used to handle business logic, API communication, data sharing, and common functionality across multiple components.

In Angular, a Service is a class used to share data, logic, or functionality across multiple components.

It follows the Singleton pattern (when provided in root), meaning one shared instance across the application.

    We use services for:
  • API calls (HTTP requests)
  • Business logic
  • State management
  • Data sharing between components
  • Reusable utility functions
  • Authentication & authorization logic

A Service is a TypeScript class used to store:

Dependency Injection (DI)

Dependency Injection is a design pattern where Angular automatically provides required objects (dependencies) to a class instead of creating them manually.

Dependency Injection is a design pattern where Angular automatically provides required dependencies to a component or service instead of creating them manually.

What is a Dependency?

A dependency is any object a class needs to perform its work.

What is @Injectable()?

Marks a class as available for Angular's Dependency Injection system.

It tells Angular that the class can participate in the Dependency Injection system.

10. Injection Token

Used when Angular cannot identify dependency type automatically.

      
        export const API_URL =
        new InjectionToken string(
        'apiUrl'
        );

        
        provide: API_URL,
        useValue:
        'https://api.com'
        

        constructor(
        @Inject(API_URL)
        private apiUrl:string
        )

Why InjectionToken?

Used to inject primitive values, configuration objects, and interfaces.

11. Factory Provider

Used when dependency creation requires custom logic.

      
        
          provide:'API_URL',

          useFactory: () => 
          

            return environment.apiUrl;

When to use Factory Provider?

When dependency creation depends on runtime conditions or configuration.
