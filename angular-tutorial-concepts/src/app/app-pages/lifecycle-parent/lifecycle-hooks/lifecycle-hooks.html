Topic 11: Angular Lifecycle Hooks

What are Lifecycle Hooks in Angular?

Lifecycle hooks are methods that allow developers to execute code at specific stages of a component or directive's lifecycle.
They are useful for initializing data, responding to input changes, accessing initialized views, and cleaning up resources.

In Angular, a component is born, updated, and destroyed.
Angular gives us lifecycle hooks — special methods that let us tap into each stage of that component’s life.
Think of them like checkpoints:
“Component created” → “Data changed” → “View rendered” → “Component destroyed”

Lifecycle hooks are special methods that Angular calls at specific moments in a component's life - from creation to destruction. They let you tap into key moments and run custom logic.

Q3. What is the difference between constructor and ngOnInit?

The constructor is a TypeScript class initialization method. It is commonly used for dependency injection and simple initialization.
ngOnInit is an Angular lifecycle hook. It runs after Angular has initialized the component's input properties.

Q4. What is the difference between ngOnChanges and ngOnInit?

ngOnChanges runs when input properties change. It can run during initial setup before ngOnInit, and it may run again for later input changes.
ngOnInit runs once after the initial input setup.

            
import 
  Component,
  Input,
  OnChanges,
  OnInit,
  SimpleChanges
 from '@angular/core';

@Component(
  selector: 'app-user',
  standalone: true,
  template: `
 name 
`
)
export class UserComponent implements OnChanges, OnInit 
  @Input() name = '';

  ngOnChanges(changes: SimpleChanges) 
    console.log('Input changed', changes);
  

  ngOnInit() 
    console.log('Component initialized');

Q5. What is the difference between ngAfterViewInit and ngAfterContentInit?

ngAfterViewInit runs after the component's own view and view children are initialized.
ngAfterContentInit runs after content projected into the component using content projection has been initialized.

Q6. What is the purpose of ngOnDestroy?

ngOnDestroy allows a component or directive to release resources before destruction. Common cleanup tasks include unsubscribing from long-lived Observables, removing manually registered event listeners, and clearing other resources.

Q7. What is the difference between ngDoCheck and ngOnChanges?

ngOnChanges responds to Angular-detected changes in input properties. ngDoCheck allows custom change checking and runs during relevant change-detection cycles.
ngDoCheck should be used cautiously because it can execute frequently.

Q8. How do you prevent memory leaks from subscriptions?

Use appropriate cleanup strategies based on the subscription lifecycle. Common approaches include the async pipe, takeUntilDestroyed(), and the takeUntil pattern.

            
import 
  Component,
  DestroyRef,
  inject,
  OnInit
 from '@angular/core';
import  takeUntilDestroyed  from '@angular/core/rxjs-interop';
import  interval  from 'rxjs';

@Component(
  selector: 'app-timer',
  standalone: true,
  template: `
Timer component
`
)
export class TimerComponent implements OnInit 
  private destroyRef = inject(DestroyRef);

  ngOnInit() 
    interval(1000)
      .pipe(takeUntilDestroyed(this.destroyRef))
      .subscribe(value => console.log(value));

The subscription is automatically cleaned up when the component is destroyed.

Q. You subscribe to a continuously running WebSocket stream in a component. What happens if you do not clean up the subscription?

The subscription may continue receiving data after the component is destroyed, potentially causing memory leaks, unnecessary processing, or attempts to update state that is no longer relevant. I would use an appropriate cleanup strategy or manage the stream at a longer-lived service level if the data needs to remain active across views.

Think of them like checkpoints:

Full Lifecycle Order (Big Picture)

  • constructor() → Component instance created
  • ngOnChanges() → Input() properties change
  • ngOnInit() → Component initialized (called once)
  • ngDoCheck() → Custom change detection
  • ngAfterContentInit() → Content projection initialized
  • ngAfterContentChecked() → Content projection checked
  • ngAfterViewInit() → View initialized
  • ngAfterViewChecked() → View checked
  • ngOnDestroy() → Component destroyed

Before Angular binds data

Why shouldn't we use constructor for initialization logic?

A: Constructor is called before Angular initializes the component. Input() properties, DOM elements, and child components aren't available. Use ngOnInit() instead for initialization logic.

2. ngOnChanges() (Input watcher)

To react to parent → child data changes

When it runs

  • Runs whenever Input() data changes
  • Runs before ngOnInit()
  • Runs multiple times

Interview Question: Q: When does ngOnChanges NOT get called?

A: ngOnChanges only fires for Input() properties. It doesn't detect changes inside objects/arrays (reference change only). For primitive types, it fires on every change. For objects/arrays, it only fires when the reference changes.

ngOnInit()

In Angular, ngOnInit() is one of the most important lifecycle hooks.

What is ngOnInit()?

ngOnInit() is a lifecycle hook that:

  • Runs once
  • Runs after Angular sets all Input() values
  • Runs after the first ngOnChanges()
  • Is used for component initialization logic

What is ngDoCheck()?

In Angular, ngDoCheck() is a lifecycle hook that allows you to manually detect and react to changes.
Runs during every change detection cycle.

    That means:
  • Runs during every change detection cycle
  • Runs after ngOnChanges()
  • Runs very frequently
  • Is used for custom change detection

When does Angular run Change Detection?

Angular runs it when:

  • User clicks
  • Input field changes
  • HTTP response returns
  • Timer / setTimeout runs
  • Promise resolves
  • Observable emits
  • Parent changes input
  • Any event occurs

ng after view init and view checked Lifecycle hook in Angular

View Lifecycle Hooks in Angular

In Angular, View means:
The component’s own template + child components inside it.

ngAfterViewInit()

ngAfterViewInit() runs:

  • After Angular initializes the component’s view
  • After ViewChild and ViewChildren are available
  • Only once

ngAfterViewChecked()

In Angular ngAfterViewChecked() is a lifecycle hook that runs after Angular checks the component’s view and child views.

It is called:

  • After ngAfterViewInit()
  • After every change detection cycle
  • After Angular checks the component’s template (view)
  • It runs many times, not once.

What is “Content” in Angular?

In Angular, Content refers to:
The projected content passed into a component using < ng-content >.

That p is content, not view.

What is ngAfterContentInit()

  • Runs after Angular projects external content into the component
  • Runs only once
  • Runs after ngAfterContentInit() is triggered
  • Used with ContentChild

Why not ngOnInit?

Because projected content is not available in ngOnInit().
ContentChild is ready only in ngAfterContentInit().

  • Modify projected content
  • Read projected child components
  • Create wrapper components (cards, modals, tabs)
  • Build reusable layout components
  • Dynamic template rendering

Interview Questions

Q1: What is projected content?

Content passed from parent to child using ng-content.

Q2: Difference between ViewChild and ContentChild?

ViewChild accesses component’s own template.
ContentChild accesses projected content.

Q3: When does ngAfterContentInit run?

After Angular projects external content into the component.

Q4: Does ngAfterContentChecked run once?

No, it runs after every change detection cycle.

Q5: Why are content hooks needed?

To interact with projected content safely after it is initialized.

What is ngAfterContentChecked()

  • Runs after Angular checks projected content
  • Runs after ngAfterContentInit()
  • Runs on every change detection cycle

ng on destroy Lifecycle hook in Angular

In Angular,
ngOnDestroy() runs just before Angular destroys a component instance.

When does it run?

It runs when:

  • You navigate to another route
  • Component is removed with *ngIf
  • Parent component gets destroyed
  • Page reloads
  • Dynamic component is removed

🧠 Why is it IMPORTANT?

Because Angular does NOT automatically clean up:

  • Subscriptions
  • Timers
  • Intervals
  • WebSocket connections
  • Event listeners

If you don’t clean them → memory leaks.
