Topic 11: Angular Signals(16+)

Angular Signals and Zoneless Angular

This section is especially important for you because you're working with modern Angular, including Angular 21. We'll focus on how Signals work, when to use them instead of RxJS, and the interview questions that test real-world understanding.

1. What are Angular Signals?

Definition: Signals are a reactive state-management primitive that holds a value and notifies Angular and other reactive consumers when that value changes.

Traditional property: count = 0;

Signal: count = signal(0);

With a normal property, Angular doesn't automatically track every assignment as a reactive dependency. A Signal explicitly tracks reads and notifies its consumers when its value changes.

Basic example

How it works

  1. signal(0) creates a writable signal with an initial value of 0.
  2. count() reads its current value.
  3. update() changes the value.
  4. Angular tracks the signal read in the template and can update the view when the signal changes.

Interview answer: Signals provide fine-grained reactivity by tracking where values are read and notifying consumers when those values change.

2. Writable signals: signal()

A writable signal supports reading and updating its value.

set() vs update()

                
set()	                                        update()
Sets a specific value.	                        Calculates a new value from the current value.
Useful when the replacement is already known.	Useful for counters and state transitions.

count.set(10);

count.update(value =>  value + 1);
The resulting count is 11.

3. computed() — derived state

A computed signal creates a read-only value derived from one or more other signals.

Angular tracks the signals read inside the computation. When a dependency changes, the computed value is recalculated when needed.

Real-world example: shopping cart

Important: A computed signal is read-only. You cannot use totalPrice.set(100).

Interview question: computed() vs effect()

  • computed() derives a value from other signals.
  • effect() performs a side effect when signals it reads change.

Use computed() for derived application state, rather than an effect that manually copies values into another signal.

4. effect() — responding to signal changes

An effect runs a callback when the signals it reads change. It is intended for side effects, such as logging or synchronizing with an external system.

The effect reads count(), so Angular tracks it as a dependency.

Important interview points

  • An effect runs initially and again when its tracked signal dependencies change.
  • Effects are intended for side effects, not routine derived-state calculations.
  • Effects need an appropriate Angular injection context unless an injector is explicitly provided.
  • Avoid creating feedback loops by repeatedly writing to signals from effects.

Common mistake: Using effect() just to keep two signals synchronized. Prefer computed() when one value can be derived from another.

5. Signals in component communication

Modern Angular provides signal-based APIs for component inputs and outputs.

input() — signal-based input

output() — component events

output() provides the modern output API. The traditional @Input() and @Output() decorators remain supported and are still important for interviews and existing projects.

input() vs model()

Angular also provides model() for two-way component APIs, where a child can update a value that is bound by the parent using banana-in-a-box syntax.

value = model(0);

Parent usage:

< app-counter [(value)]="count" />

Use model() when the component genuinely needs a two-way binding API; otherwise, a one-way input and explicit output are often clearer.

6. Signals vs Observables

This is one of the most common modern Angular interview questions.

                
Signals	                                Observables
Hold and expose a current value.	    Represent streams of values over time.
Read synchronously using mySignal().	Consume through subscription or operators.
Track reactive dependencies.	        Use RxJS operators to transform and combine streams.
Excellent for component state and derived values.	Excellent for asynchronous workflows and event streams.
No manual subscription is needed to read a signal.	Subscriptions may need lifecycle management.

When should you use Signals?

Use Signals for:

  • Selected tabs and filters
  • Component UI state
  • Derived values
  • Counters and totals
  • Synchronous application state

Use RxJS for:

  • HTTP and asynchronous workflows
  • Search with debounceTime() and switchMap()
  • Combining API requests
  • WebSocket streams
  • Cancellation and retry patterns

Experienced-developer answer: Signals and RxJS solve related but different problems. I use Signals for reactive state and derived UI values, and RxJS for asynchronous streams and more complex event orchestration. They can be combined rather than treated as alternatives.

7. RxJS and Signals interoperability

Angular provides utilities in @angular/core/rxjs-interop for integrating the two reactive systems.

toSignal()

Converts an Observable into a signal, allowing the latest emitted value to be read synchronously.

toSignal() subscribes to the Observable and normally cleans up that subscription with its owning injection context. It should not be recreated repeatedly inside a template or frequently called method.

toObservable()

Converts a signal into an Observable.

This is a useful pattern when the UI state is represented by a signal but the workflow needs RxJS operators.

When would you use toSignal() instead of subscribe()?

When the component needs to read an Observable's latest value as reactive state, especially in the template. It can simplify code and avoid managing a manual subscription just to display data.

8. Signal-based state management

You can create a lightweight state service using Signals without introducing NgRx.

Example: selected user state.

Why asReadonly()?

It prevents consumers from calling set() or update() on the exposed signal. The service retains control over state updates through its methods.

Important: Read-only signals prevent consumers from directly setting the signal value, but they don't make nested objects deeply immutable. Use immutable updates and appropriate data modeling.

Signals vs NgRx

  • Signals alone are often sufficient for local component state or straightforward shared state.
  • NgRx can be useful for large applications requiring structured state transitions, effects, selectors, tooling, and consistent team conventions.

9. What is zoneless Angular?

Traditionally, Angular commonly used Zone.js to observe asynchronous activity and help determine when change detection should run.

Zoneless Angular operates without relying on Zone.js for those notifications. Instead, Angular uses supported notifications, including signal updates, bound events, AsyncPipe emissions, and explicit view marking.

In Angular 21, zoneless change detection is the default for newly configured applications. Existing applications may have different configurations depending on how they were created or upgraded.

Why use zoneless Angular?

  • Reduces reliance on Zone.js.
  • Can reduce unnecessary change-detection work.
  • Encourages explicit, trackable update notifications.
  • - Can improve application startup and runtime characteristics in suitable applications.

Zoneless does not automatically guarantee better performance; results depend on the application and how its state updates are designed.

Do Signals require zoneless Angular?
No. Signals work in both Zone.js-based and zoneless applications.

10. Configuring zoneless change detection

For an application that needs explicit zoneless configuration, Angular provides provideZonelessChangeDetection().

For a newly created Angular 21 application, zoneless is already the default, so you generally don't need to add this provider again. Check your application's existing configuration before changing it.

When using zoneless Angular, make sure your UI updates are driven by supported Angular notifications, such as:

  • Updating a signal read by the template.
  • Bound event handlers.
  • AsyncPipe emissions.
  • Calling markForCheck() when appropriate.

What are Signals in Angular?

  • Automatically track dependencies
  • Update the UI when data changes
  • Avoid manual subscriptions (like RxJS subscribe())
