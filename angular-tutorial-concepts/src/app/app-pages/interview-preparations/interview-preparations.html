Q3. What is a single-page application (SPA)?

A single-page application is a web application that loads an initial HTML page and updates its content dynamically as users interact or navigate, usually without a full browser-page reload.
Angular commonly uses client-side routing to build SPAs.

Example:

Consider an employee management application with:

  • /dashboard
  • /employees
  • /reports
  • /settings

Cross-question: What are the advantages and disadvantages of SPAs?

Advantages:

  • Smooth navigation.
  • Reusable client-side UI.
  • Efficient transitions between views.
  • Clear separation between frontend and backend APIs.

Disadvantages:

  • Initial loading and bundle size require attention.
  • SEO may require server rendering or prerendering.
  • Client-side routing and browser history need proper configuration.
  • - Authentication and client-side security need careful handling.

3. Standalone Components

A standalone component is a component that can directly declare its own imports and doesn't need to belong to an NgModule. It simplifies application structure and is the recommended approach for modern Angular applications.

Modern Angular applications commonly use standalone components.

Standalone components reduce the need for traditional NgModule organization.

            
                @Component(
                    selector: 'app-user',
                    standalone: true,
                    imports: [CommonModule],
                    templateUrl: './user.component.html'
                )
                export class UserComponent

Q2. What are the advantages of standalone components?

  • They reduce the need for NgModule boilerplate.
  • Component dependencies are explicit.
  • They simplify bootstrapping.
  • They support direct lazy loading of routed components.
  • They can make feature organization and migration easier.

Q4. How do you lazy-load a standalone component?

Use loadComponent in the route configuration.

            
                import  Routes  from '@angular/router';

                export const routes: Routes = [

Q5. What is the difference between loadComponent and loadChildren?

  • loadComponent lazy-loads a single component for a route.
  • loadChildren lazy-loads child route definitions or an NgModule.

Q6. Can standalone components use NgModules?

Yes. A standalone component can import an NgModule in its imports array to use the declarations that the module exports. Similarly, an NgModule can import a standalone component.

Q7. What is bootstrapApplication()?

bootstrapApplication() is an Angular API used to bootstrap an application using a standalone root component and optional application configuration.

            
                import  bootstrapApplication  from '@angular/platform-browser';
                import  provideRouter  from '@angular/router';
                import  AppComponent  from './app/app.component';
                import  routes  from './app/app.routes';

                bootstrapApplication(AppComponent, 
                providers: [provideRouter(routes)]
                );

Q. You have a large application with 30 feature areas. How would standalone components help?

Standalone components let each feature import its direct dependencies without requiring a separate NgModule for every feature. I would combine that with lazy-loaded routes and feature-oriented organization to keep the application modular.

Q6. What is the difference between core, shared, and feature folders?

  • Shared: Often contains reusable UI components, pipes, directives, and utilities.

Topic 8: Data Binding

Q1. What is data binding in Angular?

Data binding connects component data and behavior to a template. It allows Angular to display values, set element properties, respond to events, and synchronize values between the component and the view.

Q2. What are the different types of data binding?

Angular supports four commonly discussed types:

  1. Interpolation
  2. Property binding.
  3. Event binding.
  4. Two-way binding.

Q3. What is interpolation?

Interpolation uses double curly braces to display an expression's result as text in a template.

1. Interpolation: {{ name }}

Q4. What is property binding?

Property binding sets a DOM property or component input using an expression from the component.

Q5. What is event binding?

Event binding listens for an event and executes a template expression when the event occurs.

Q6. What is two-way data binding?

Two-way binding combines a value flowing from the component to the view with an event that updates the component from the view.

This is called banana-in-a-box syntax.

Q. You have a search input that should filter a table as the user types. How would you implement it?

For a simple local table, I would use event binding or a form control to capture the search term and derive the filtered list. For API-based search, I would use an input stream with operators such as debounceTime, distinctUntilChanged, and switchMap to avoid unnecessary requests.

Q4. Pure vs Impure Pipes

A pure pipe is the default. It executes when Angular detects a change to its input value or reference. An impure pipe can execute during every relevant change-detection cycle.

            
                Pure pipe	                    Impure pipe
                Default	                        Requires pure: false
                Runs on input changes	        Can run frequently
                Usually more efficient	        May be more expensive
                Good for most transformations	Appropriate only for specific cases

A Pure Pipe is a pipe that Angular executes only when the input value or input reference changes. Pure pipes are optimized for performance because Angular avoids running them unnecessarily. By default, all Angular pipes are Pure Pipes.

                @Pipe(
                name: 'myPipe',
                pure: true
                )

An Impure Pipe is a pipe that Angular executes during every change detection cycle, regardless of whether the input reference changed or not. Impure pipes are useful when data changes internally without creating a new object or array reference.
The important part:
pure: false
This tells Angular to run the pipe on every change detection cycle.

                @Pipe(
                name: 'myPipe',
                pure: false
                )

Q5. Can we chain pipes?

Yes. The output of one pipe can be passed to another.

                    
 today | date:'fullDate' | uppercase

Q6. Can pipes accept parameters?

Yes. Parameters are passed after the pipe name using colons.

 amount | number:'1.2-2'

Q7. Why should expensive operations be avoided inside pipes?

Pipes can be evaluated as part of template update processing. Expensive transformations, especially in impure pipes, can affect rendering performance. Complex calculations may be better placed in a service or derived state.

Q. You need to filter and sort a large table. Would you use a custom pipe?

For a small, simple list, a pure custom pipe may be appropriate. For large data, frequent updates, or server-backed filtering, I would consider derived state, a dedicated data-processing layer, or server-side operations to avoid repeated expensive calculations.

Topic 11: Angular Lifecycle Hooks

What are Lifecycle Hooks in Angular?

Lifecycle hooks are methods that allow developers to execute code at specific stages of a component or directive's lifecycle.
They are useful for initializing data, responding to input changes, accessing initialized views, and cleaning up resources.

In Angular, a component is born, updated, and destroyed.
Angular gives us lifecycle hooks — special methods that let us tap into each stage of that component’s life.
Think of them like checkpoints:
“Component created” → “Data changed” → “View rendered” → “Component destroyed”

Lifecycle hooks are special methods that Angular calls at specific moments in a component's life - from creation to destruction. They let you tap into key moments and run custom logic.

The constructor is a TypeScript class initialization method. It is commonly used for dependency injection and simple initialization.

Q4. What is the difference between ngOnChanges and ngOnInit?

ngOnChanges runs when input properties change. It can run during initial setup before ngOnInit, and it may run again for later input changes.
ngOnInit runs once after the initial input setup.

Q5. What is the difference between ngAfterViewInit and ngAfterContentInit?

ngAfterViewInit runs after the component's own view and view children are initialized.
ngAfterContentInit runs after content projected into the component using content projection has been initialized.

Q6. What is the purpose of ngOnDestroy?

ngOnDestroy allows a component or directive to release resources before destruction. Common cleanup tasks include unsubscribing from long-lived Observables, removing manually registered event listeners, and clearing other resources.

Q7. What is the difference between ngDoCheck and ngOnChanges?

ngOnChanges responds to Angular-detected changes in input properties. ngDoCheck allows custom change checking and runs during relevant change-detection cycles.
ngDoCheck should be used cautiously because it can execute frequently.

Q8. How do you prevent memory leaks from subscriptions?

Use appropriate cleanup strategies based on the subscription lifecycle. Common approaches include the async pipe, takeUntilDestroyed(), and the takeUntil pattern.

            
import 
  Component,
  DestroyRef,
  inject,
  OnInit
 from '@angular/core';
import  takeUntilDestroyed  from '@angular/core/rxjs-interop';
import  interval  from 'rxjs';

@Component(
  selector: 'app-timer',
  standalone: true,
  template: `
Timer component
`
)
export class TimerComponent implements OnInit 
  private destroyRef = inject(DestroyRef);

  ngOnInit() 
    interval(1000)
      .pipe(takeUntilDestroyed(this.destroyRef))
      .subscribe(value => console.log(value));

The subscription is automatically cleaned up when the component is destroyed.

Q. You subscribe to a continuously running WebSocket stream in a component. What happens if you do not clean up the subscription?

The subscription may continue receiving data after the component is destroyed, potentially causing memory leaks, unnecessary processing, or attempts to update state that is no longer relevant. I would use an appropriate cleanup strategy or manage the stream at a longer-lived service level if the data needs to remain active across views.

Answer: Implement a CanDeactivate guard. Check whether the form is dirty and display a confirmation dialog before allowing navigation.

Scenario 3: Your application has 20 feature modules, and its initial load is slow. What would you do?

Answer: Identify large features and introduce lazy loading using loadComponent or loadChildren. Analyze bundle sizes, use preloading where appropriate, and avoid loading rarely used feature code initially.

Scenario 4: You navigate from /users/101 to /users/102, but the displayed user information does not change. Why?

Answer: Angular may reuse the same component for both URLs. If the component reads the ID only once using snapshot, it will not automatically respond to the changed ID. Subscribe to paramMap or use a reactive approach such as toSignal().

Scenario 5: A user filters a table, opens a record, and then returns. You want to preserve the table filters and page number. How would you do it?

Answer: Store shareable filter and pagination state in query parameters. When returning to the table, read those parameters and restore the relevant state. This also allows users to bookmark or share the filtered URL.

Scenario 6: Your admin application has a common sidebar and header, but different content for each menu item. How would you structure routing?

Answer: Create a parent admin layout with a router-outlet, then define child routes for the dashboard, users, reports, and settings. This keeps the shared layout consistent while route-specific components change.

Scenario 7: A reports feature is available only to users whose organization has enabled it. How would you handle this?

Answer: Use CanMatch to decide whether the reports route should match based on the feature configuration. Also enforce the relevant access rules on the server.

Scenario 8: A route requires data from an API before it should open. What would you use?

Answer: Use a resolver if navigation should wait for essential data. If the page can render with a loading indicator while data loads, fetching in the component or a dedicated data layer may provide a better experience.

12. Important form states

Every Angular form control has several useful states.

                
| Property      | Meaning                                           |
|---            |                                                ---|
| `valid`       | All validators pass |
| `invalid`     | At least one validator fails |
| `touched`     | User has interacted with the control and left it |
| `untouched`   | User hasn't blurred/interacted with it |
| `dirty`       | Value has changed |
| `pristine`    | Value hasn't changed |
| `enabled`     | Control accepts interaction |
| `disabled`    | Control is disabled |
| `pending`     | Async validation is in progress |

Very common interview question

touched means the user has interacted with the control and it has lost focus.
dirty means the control's value has been changed.

For example: Click input → type nothing → click outside

The control can become:
touched = true
dirty = false

But: Click input → type something, makes it: dirty = true

2. Signals

What is a Signal?

A Signal is Angular's reactive primitive for holding a value and notifying Angular when that value changes.

Count example

count = signal(0);

to read

this.count()

to update

this.count.set(10);

or

this.count.update(value => value + 1);

Why were Signals introduced?

Signals provide fine-grained reactivity. Instead of Angular having to evaluate a broad component tree during change detection, Signals allow Angular to understand which pieces of state depend on which values. They make state management simpler for many component-level use cases and work particularly well with modern Angular's reactive rendering model.

signal() vs computed() vs effect()?

signal()
Stores state.
count = signal(10);
computed()
Creates derived/read-only state. 
            count = signal(10);
            doubleCount = computed(() => this.count() * 2);
effect()
Runs side effects when signals it reads change. 
                
                    effect(() => 
        console.log(this.count());
        );

Interview answer:

I use Signals for state, computed for derived state, and effects only for side effects such as logging, local storage synchronization, or interacting with an external API. I avoid using effects for normal derived business logic because computed is more appropriate.
