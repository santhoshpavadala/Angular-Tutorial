Angular Routing

Routing is the mechanism that enables navigation between different views/components in an Angular application without reloading the browser. Angular uses the Router to map URLs to Components. Angular loads: without refreshing the page.

Definition: Angular Routing is a mechanism that allows users to navigate between different views or components of a single-page application (SPA) without reloading the entire page.

For example, an application might have these routes:

            
URL	        Component
/home	    HomeComponent
/users	    UsersComponent
/users/101	UserDetailsComponent
/login	    LoginComponent

When the URL changes, Angular Router determines which component should be displayed.

Why do we use routing?

  • To navigate between pages without a full page reload.
  • To organize large applications into feature routes.
  • To support route parameters and query parameters.
  • To protect routes with guards.
  • To load feature code only when required.

7. Lazy loading

Definition: Lazy loading is a technique in which Angular loads a component or feature's code only when the associated route is visited, rather than including all feature code in the initial application load.

It can improve initial loading performance for larger applications.

Preloading strategies

Preloading allows Angular to load lazy routes in the background after the initial application load.

This preloads lazy-loaded routes as a strategy to reduce the delay when users navigate to them later. It does not mean that all features are eagerly loaded into the initial bundle.

Interview question: Does lazy loading always improve performance?

Answer: No. It can reduce initial bundle size, but it can also introduce delays when a user first navigates to a lazy-loaded feature. The best strategy depends on application size, usage patterns, and network conditions.

8. Route guards

Definition: Route guards control whether navigation to or away from a route is allowed.

They are useful for authentication flows, authorization checks, preventing accidental navigation away from unsaved forms, and controlling access to route branches.

Angular supports several guard types:

                
Guard	            Purpose
CanActivate	        Controls whether a route can be activated.
CanActivateChild	Controls access to child routes.
CanDeactivate	    Controls whether a user can leave a route.
CanMatch	        Controls whether a route configuration can match a URL.

In modern Angular, functional guards are commonly used.

CanActivate example

If the user is not logged in, Angular redirects to the login page.

This is a simplified frontend example. In a real application, authentication state should be managed appropriately, and the backend must independently enforce authorization. A route guard is not a security boundary by itself.

CanActivateChild example

The guard applies to child routes under the admin route.

CanDeactivate example

This is especially useful for preventing users from losing unsaved form changes.

CanMatch example

CanMatch determines whether a route can be selected to match the URL.

It can be used for feature flags or selecting between route configurations. Unlike a failed CanActivate, a CanMatch result of false allows the router to consider other matching route configurations.

What can a guard return?

A guard can return:

  • true to allow navigation.
  • false to block navigation.
  • A UrlTree or RedirectCommand to redirect.
  • A Promise or Observable that resolves to one of the supported results.

Interview question: What is the difference between CanActivate and CanMatch?

  • CanActivate checks whether an already matched route can be activated.
  • CanMatch checks whether a route configuration can be used to match the requested URL in the first place.

9. Route resolvers

Definition: A resolver fetches or prepares data before a route is activated. It is useful when the destination component requires data to render correctly.

For example, when navigating to /users/101, the user details may need to be fetched before the details component is activated.

Create a resolver

Resolver vs fetching inside the component

                
Resolver	                        | Component-level fetching
Runs as part of route activation.	| Runs after the component is created or when its logic triggers it.
Useful when the route should wait for essential data.	| Useful for optional data, progressive loading, and interactive refreshes.
Can delay navigation until required data is ready.	| Can display the page immediately with a loading state.

Important: Resolvers can fail or take a long time. Real applications should handle errors and loading behavior thoughtfully. Use a resolver only when waiting for data before activating the route is a good user experience.

12. Important Angular Routing interview questions and answers

Q1. What is Angular Router?

Angular Router is the built-in navigation system that maps URL paths to components and manages navigation in an Angular application.

Q2. What is RouterOutlet?

RouterOutlet is a directive that acts as a placeholder where the router displays the component for the active route.

Q3. What is the difference between RouterModule.forRoot() and RouterModule.forChild()?

  • forRoot() configures the router at the application's root, typically in an NgModule-based application.
  • forChild() registers additional routes for feature modules without creating a separate root router.

    • In standalone applications, provideRouter() is the common root configuration approach.

Q4. What is a wildcard route?

A wildcard route uses ** to match URLs that have not matched earlier route definitions. It is commonly used for a not-found page.

Q5. What is the difference between navigate() and navigateByUrl()?

navigate() accepts route commands, while navigateByUrl() accepts a complete URL or UrlTree.

Q6. What is lazy loading?

Lazy loading loads route-associated code only when required instead of including all feature code in the initial loading path.

Q7. What is route reuse?

Route reuse is a router mechanism that can reuse existing route components rather than destroying and recreating them during navigation. Angular's default strategy reuses a component when navigating between routes that share the same route configuration, which is why parameter changes may need reactive handling.

Intermediate interview questions

Q8. What happens if a route guard returns false?

Navigation is canceled for that guard. If the guard returns a redirect result, Angular navigates to the specified destination instead.

Q9. Can multiple guards be applied to a route?

Yes. Multiple guards can be configured. Angular evaluates them as part of the navigation process, and their results determine whether navigation can proceed.

Q10. What is the difference between route parameters and query parameters?

Route parameters are part of the route path and commonly identify a resource. Query parameters are optional URL parameters commonly used for filtering, pagination, sorting, or search.

Q11. Can we apply guards to lazy-loaded routes?

Yes. Guards such as CanMatch can control whether a lazy route configuration matches. Other applicable guards can control activation and access to child routes.

Q12. What is a resolver in Angular?

A resolver prepares data before activating a route. It is useful when a component needs essential data before it can render.

Q13. What is the purpose of ActivatedRoute?

ActivatedRoute provides information about the currently activated route, including parameters, query parameters, route data, and parent or child route information.

Q14. How do you pass data while navigating?

You can pass query parameters, route parameters, or navigation state.

                
                    this.router.navigate(['/users'], 
                    
                        state: 
                        
                             source: 'dashboard' 
                        
                    
                    );

Navigation state is available through the router's navigation extras and browser history state. It is not a substitute for URL-based data that needs to be shareable or reliably restored.

Q15. What is queryParamsHandling: 'merge'?

It merges the supplied query parameters with existing query parameters instead of replacing the existing set.

13. Real-world scenario-based interview questions

Scenario 1: A user should not access the dashboard without logging in. How would you implement it?

Answer: Use a CanActivate guard to check authentication state and redirect unauthenticated users to the login page. Also enforce authorization on the backend, because client-side guards can be bypassed.

Scenario 2: A user edits a form and clicks another page without saving. How do you prevent data loss?

Answer: Implement a CanDeactivate guard. Check whether the form is dirty and display a confirmation dialog before allowing navigation.

Scenario 3: Your application has 20 feature modules, and its initial load is slow. What would you do?

Answer: Identify large features and introduce lazy loading using loadComponent or loadChildren. Analyze bundle sizes, use preloading where appropriate, and avoid loading rarely used feature code initially.

Scenario 4: You navigate from /users/101 to /users/102, but the displayed user information does not change. Why?

Answer: Angular may reuse the same component for both URLs. If the component reads the ID only once using snapshot, it will not automatically respond to the changed ID. Subscribe to paramMap or use a reactive approach such as toSignal().

Scenario 5: A user filters a table, opens a record, and then returns. You want to preserve the table filters and page number. How would you do it?

Answer: Store shareable filter and pagination state in query parameters. When returning to the table, read those parameters and restore the relevant state. This also allows users to bookmark or share the filtered URL.

Scenario 6: Your admin application has a common sidebar and header, but different content for each menu item. How would you structure routing?

Answer: Create a parent admin layout with a router-outlet, then define child routes for the dashboard, users, reports, and settings. This keeps the shared layout consistent while route-specific components change.

Scenario 7: A reports feature is available only to users whose organization has enabled it. How would you handle this?

Answer: Use CanMatch to decide whether the reports route should match based on the feature configuration. Also enforce the relevant access rules on the server.

Scenario 8: A route requires data from an API before it should open. What would you use?

Answer: Use a resolver if navigation should wait for essential data. If the page can render with a loading indicator while data loads, fetching in the component or a dedicated data layer may provide a better experience.

CanMatch

CanMatch is an Angular route guard that determines whether a route should match the current URL. It is particularly useful with lazy-loaded routes because it can prevent a route from being selected based on conditions such as user roles or permissions. Unlike canActivate, when canMatch returns false, Angular can continue looking for another route that matches the same URL.

CanMatch is a route guard that determines whether Angular should match a route at all.

canMatch decides whether a route is eligible to be matched before Angular activates or lazy-loads that route. This makes it especially useful for role-based routing and lazy-loaded features.
